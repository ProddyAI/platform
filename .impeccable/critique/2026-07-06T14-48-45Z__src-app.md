## Anti-Patterns Verdict

The core workspace shell (sidebar, toolbar, command palette) would largely earn a Linear/Notion user's trust: dense purple chrome used consistently, collapsed-sidebar tooltips, a real ⌘K palette with grouped results, and loading/empty/error triads on most routes. But trust collapses at the edges. The video-meet surface is a different product entirely — a Google-Meet-derived hex palette (#0a0a12, #3c4043, #0b57d0), indigo accent instead of the purple/pink tokens, per-word animated captions, and "your AI intelligence has been safely saved" copy. The 404 page is a jokey marketing artifact with blur blobs, a glass card, and an uppercase tracked kicker inside a product app. The error page dumps raw error.message on a red screen. The About page uses "work smarter, not harder" — the exact hype line PRODUCT.md names as an anti-reference. And dark mode is held together by a `.dark [class*="bg-white"] { !important }` rewrite in globals.css because a dozen route pages hard-code bg-white and gray-* text. It reads as one disciplined core surface surrounded by AI-generated satellite surfaces that were never reconciled into the "one system" the brief demands.

**Deterministic scan**: 18 findings — ai-color-palette ×9, gray-on-color ×7, bounce-easing ×1, border-accent-on-rounded ×1.
Suspected false positives: 7 (meeting-components.tsx:652 gray-on-color — text-gray-300 is the unselected ternary branch; the indigo bg belongs to the other branch (and is a 10% tint); meet/[meetingId]/page.tsx:480 gray-on-color — conditional className; gray-400 pairs with bg-white/5, not bg-indigo-500; meet/[meetingId]/page.tsx:492 gray-on-color — same conditional pattern as line 480; meeting-notes/page.tsx:285 gray-on-color — text-gray-600 pairs with bg-gray-100 in the fallback status branch, not emerald-100; meeting-notes/)

## Cognitive Load

- Chunking >4: the sidebar exposes 8 top-level groups (Dashboard, Proddy AI, Channels, Projects, Members, Planning, Messages, Settings) with only one Separator; Reports has 7 tabs, Manage 5 — no grouping or overflow strategy (sidebar.tsx, reports/page.tsx, manage/page.tsx).
- One decision at a time: channel edit dialog (channel/[channelId]/layout.tsx) mixes rename, emoji picker, image upload, and the destructive 'Delete channel' button inside the same form column, with the delete button placed under the name input.
- >4 visible options per decision point: not-found.tsx presents 5 equal-weight buttons for a single 'where do I go' decision; meet bottom bar shows 9 controls in one row with no grouping beyond a divider.
- Working-memory bridge: workspace switching is dropdown → 'Switch Workspace' → separate Dialog — two hops where peers (Slack/Linear) list workspaces directly in the first menu (header.tsx).
- No single focus: meeting-notes NoteCard expands into a version selector + 4 emoji tabs + 3 export buttons + push-to-dashboard simultaneously (meeting-notes/page.tsx).
- Hidden state: Channels/Projects/Members accordions are mutually exclusive and reset on every navigation (component state derived from route at mount), so the user's expansion choices silently vanish (sidebar.tsx).

## What's Working

- Command palette (toolbar.tsx) is genuinely good: ⌘K global shortcut, grouped results (messages/notes/tasks/cards/board issues/statuses/calendar), AI-search toggle with mapped error messages, empty-query suggestions of channels and members.
- Sidebar collapse pattern done properly: Convex-persisted collapsed state, right-side Hint tooltips on every collapsed icon, mobile overlay with an accessible backdrop button and safe scroll containment.
- Most workspace routes ship the full loading/empty/error triad with purposeful empty-state copy that teaches the next action (tasks, issues, threads, outbox, notes, channel chats).
- Board page implements real optimistic drag-and-drop with revert-on-error and deliberate reconciliation against server state — 'fast is a feature' honored.
- Password reset flow is careful: 2-minute cooldown with live countdown, strength indicator, defensive JSON parsing of API responses, distinct success/invalid-token/verifying states.
- Mobile responsiveness is structural, not fluid: dedicated bottom nav (mobile-footer.tsx), Sheet-based task filters, safe-area padding, sidebar becomes an overlay.

## Priority Issues

### [P1] The /meet surface is a different design system: hard-coded hex palette (#0a0a12, #050505, #12121a, #3c4043, #4d5154, #0b57d0, #c2e7ff), indigo accent replacing the purple/pink tokens, rounded-[32px] glass cards, glow shadows, animate-bounce hand pill, per-word staggered caption animation (100ms/word), and AI-as-magic copy ('Your transcript and AI intelligence have been safely saved').

**Why**: PRODUCT.md's first promise is 'one coherent surface instead of five disconnected ones.' A user who joins a meeting from a Proddy channel lands in what looks like a re-skinned Google Meet — the exact bolted-together feeling the product exists to eliminate. Decorative motion (word-by-word captions, pulsing speaker auras) also violates 'motion with meaning' and the reduced-motion mandate (no prefers-reduced-motion anywhere).

**Fix**: Rebuild the meet chrome on tokens: bg-background/bg-card surfaces, primary/secondary accents, --duration-* transitions. Replace the caption word-stagger with a single fade, drop the bounce/ping/aura animations behind prefers-reduced-motion, title the meeting by name (not UUID slice), and rewrite the leave-modal copy in product voice ('Transcript saved to your workspace.').
**Files**: src/app/meet/[meetingId]/page.tsx, src/app/meet/[meetingId]/meeting-components.tsx

### [P1] Invalid nested interactive controls in the sidebar: DroppableItem renders the '+ New' shadcn Button inside its section-toggle <button>, and MobileCloseWrapper wraps SidebarItem/ChannelItem/MemberItem links (anchors, some themselves Buttons) inside a <button>.

**Why**: button-inside-button and a-inside-button are invalid HTML — screen readers announce one control and swallow the other, keyboard focus order is unpredictable, React can hydrate inconsistently, and clicking the '+' relies on stopPropagation to not toggle the section. Sam (keyboard/SR user) cannot reliably reach 'New Channel' at all.

**Fix**: Make the section header a flex row of sibling controls: <button> for toggle + separate <button> for the plus action. For MobileCloseWrapper, attach the onClose to the child link's onClick (or use a context/event delegation) instead of wrapping in a button.
**Files**: src/app/workspace/[workspaceId]/sidebar.tsx, src/app/workspace/[workspaceId]/options.tsx

### [P1] The global WorkspaceToolbar is mounted per-page instead of in the layout, and two pages simply lost it: meeting-notes/page.tsx and billing/page.tsx have no toolbar (no ⌘K search, no notifications, no user menu, no theme toggle). usage/page.tsx renders its title as an <h1> with hover:bg-white/10 while every other page renders a focusable Button that does nothing when activated.

**Why**: Alex lands on Meeting Notes and the app's primary navigation affordances vanish — search and notifications are only reachable by leaving the page. The fake page-title Buttons put a no-op interactive element first in every page's tab order (hover feedback promises an action that never comes) — a textbook invented affordance.

**Fix**: Move WorkspaceToolbar into workspace/[workspaceId]/layout.tsx with a slot/context for the page title, so every route gets it for free. Render titles as non-interactive <h1> (no hover style, no focusability) unless they genuinely open something (channel dialog, member profile).
**Files**: src/app/workspace/[workspaceId]/toolbar.tsx, src/app/workspace/[workspaceId]/layout.tsx, src/app/workspace/[workspaceId]/meeting-notes/page.tsx, src/app/workspace/[workspaceId]/billing/page.tsx, src/app/workspace/[workspaceId]/usage/page.tsx

### [P1] Error surfaces violate the register three ways: workspace/error.tsx dumps raw error.message in a mono block on an off-token bg-red-50 screen titled 'Something went wrong in /workspace!'; not-found.tsx is a jokey marketing page (blur blobs, glassmorphism card, uppercase tracked kicker 'Error 404: Route escaped containment', 'Reality glitched for exactly one route', 5 equal-weight CTAs including 'See Pricing'); global-error.tsx renders Next's bare default with statusCode 0.

**Why**: PRODUCT.md: 'Calm under load. The tone doesn't change when things get busy or break.' Leaking internal error strings to operators mid-work is both unprofessional and a mild info-disclosure risk; the 404's joke copy and pricing CTA read as a different company; five buttons for one decision is pure cognitive load.

**Fix**: workspace/error.tsx: token colors, one calm sentence, digest-only reference, 'Try again' + 'Go to workspaces'. not-found.tsx: one heading ('Page not found'), one sentence, Go back + Dashboard/Home — delete the blobs, glass, kicker, and joke list. global-error.tsx: minimal branded fallback with a reload action.
**Files**: src/app/workspace/error.tsx, src/app/not-found.tsx, src/app/global-error.tsx

### [P2] Dark mode is implemented as a global `!important` rewrite (`.dark [class*="bg-white"] {...}` in globals.css) because route pages hard-code light values: bg-white containers (tasks, threads, outbox, calendar, manage, meeting-notes), gray-900/gray-500 text and gray-200 borders with no dark variants (issues/page.tsx), bg-[#f6f8fb] (usage), bg-slate-50/50 (billing), dark:bg-gray-950 (board).

**Why**: This is the root token-discipline failure of the module group. Every new bg-white gets silently themed by an attribute-selector hack with !important, which makes intentional light surfaces impossible, breaks specificity everywhere, and pages like issues/page.tsx that use gray-* text produce illegible dark-mode output the hack can't fix. 'A button is a button everywhere' cannot survive this.

**Fix**: Migrate page surfaces to bg-background/bg-card/text-foreground/border-border tokens route by route, then delete the [class*="bg-white"] override and the .dark bg-secondary pink-button overrides from globals.css.
**Files**: src/app/globals.css, src/app/workspace/[workspaceId]/issues/page.tsx, src/app/workspace/[workspaceId]/tasks/page.tsx, src/app/workspace/[workspaceId]/calendar/page.tsx, src/app/workspace/[workspaceId]/threads/page.tsx, src/app/workspace/[workspaceId]/outbox/page.tsx, src/app/workspace/[workspaceId]/usage/page.tsx

### [P2] Root layout viewport sets maximumScale: 1 and userScalable: false, blocking pinch-zoom app-wide.

**Why**: Directly fails WCAG 1.4.4 (Resize Text) — and this app renders 8px and 10px type (calendar event metadata text-[8px], toolbar kbd text-[10px], meet labels), so low-vision users have tiny text AND no zoom. PRODUCT.md: 'Accessible by default… non-negotiable.'

**Fix**: Remove maximumScale/userScalable from the Viewport export in src/app/layout.tsx; audit text-[8px]/text-[10px] usages up to a 11px floor (calendar event meta, toolbar kbd).
**Files**: src/app/layout.tsx, src/app/workspace/[workspaceId]/calendar/page.tsx

### [P2] Marketing/legal pages ship named anti-references and false content: about/page.tsx says 'work smarter, not harder' (verbatim in PRODUCT.md's anti-reference list); features/page.tsx has an uppercase kicker pill ('MODULAR PRODUCTIVITY SUITE'), 'the ultimate productivity platform' hype, and dynamic Tailwind classes (`from-${color}-50`, `hover:border-${color}-200`) that Tailwind cannot generate so the styles are silently dead; privacy and terms render 'Last updated: {new Date()}' — always today's date, a false legal claim; contact/page.tsx's form is a setTimeout simulation that discards the message while showing 'sent successfully'.

**Why**: The brand explicitly bans this copy; the fake last-updated date is a trust/legal problem; a contact form that pretends to send is a dark pattern; the broken dynamic classes mean the feature cards' accent system never renders.

**Fix**: Rewrite hero copy in the brief's voice; hard-code real last-updated dates; wire the contact form to a real endpoint (or replace with a mailto); replace dynamic class interpolation with a static map of complete class strings.
**Files**: src/app/about/page.tsx, src/app/features/page.tsx, src/app/privacy/page.tsx, src/app/terms/page.tsx, src/app/contact/page.tsx
